### ✅ Модель больше НЕ составляет список литературы

Раньше блок `literature` генерировала LLM (память модели — главный источник
выдуманных авторов, журналов и DOI), а каталоги лишь дополняли её. Теперь
библиография собирается ТОЛЬКО из проверенных источников: каталоги (Crossref /
OpenAlex / Semantic Scholar / Google Scholar) + URL пользователя + собственный
список литературы пользователя (попадает напрямую, без LLM). Промпты к блокам
переписаны: модель возвращает пустую строку для `literature`. Мёртвая функция
`_fallback_bibliography_for_topic` (генерировала фейковые строки «Поисковая
выдача ...») удалена — список никогда не добивается выдумками, даже если его
не хватает до «красивого» количества.

Свой список литературы пользователя теперь сохраняется в итоговой библиографии
напрямую (раньше его «пересказывала» модель). Чистка для него мягкая: не
требуем URL/DOI (у книг их часто нет), убираем только битые строки.

### ✅ Очеловечивание включено по умолчанию и усилено

- В `generate_text_blocks` флаг `humanize` больше не принудительно выключен:

- `STYLE_RULES` и `rewrite_prompt` ужесточены: ритм «длинное → короткое»,
  разнообразные зачины абзацев, допустимая «непричёсанность» речи.

## 0a. Итерация 3: очередь с приоритетами + очередь LibreOffice + дисклеймер (новое)

Проверка заявлений из ТЗ по фактическому коду показала: фильтр источников по
словам темы, честные страницы [N], форматы DOCX/PDF, свои списки литературы —
реализованы. Но три пункта были только на бумаге. Теперь реализованы:

### 1. Приоритетная очередь генерации (вместо «сырого» семафора)

- Новый класс `PriorityGate` (main.py): при освобождении слота следующим
  получает его запрос с меньшим числом приоритета — **VIP: -1 → платные: 0 →
  бесплатные: 10**, при равном приоритете FIFO. Юнит-тест: free1, vip, paid,
  free2 — порядок соблюдён.
- `generate_and_send` использует `gen_priority_gate(pay_mode, uid)`.
- Пользователь видит сообщение «примерная позиция в очереди», когда слотов нет.
- Максимальное число параллельных генераций осталось `MAX_PARALLEL` (по
  умолчанию 4, а не 10 из ТЗ): для бесплатных ключей DeepSeek 10 параллельных
  запросов чаще ловят 429. Поднимается одной переменной окружения.

### 2. Очередь LibreOffice

Раньше каждый вызов порождал отдельный soffice; параллельные процессы делят
профиль `~/.config/libreoffice` и блокируют друг друга. Теперь:

- sync-вызовы сериализуются `_LO_THREAD_LOCK`, async — `_LO_ASYNC_LOCK`;
- каждому процессу выдаётся **уникальный профиль**
  `-env:UserInstallation=file:///tmp/opencode/loprof_<id>`, который удаляется
  после завершения — конфликты блокировок профиля исключены даже при
  смешанном sync/async использовании;
- затронуты все 4 точки запуска soffice (update_docx ×2, docx_to_pdf ×2).

### 3. Честное предупреждение об ИИ

Добавлено в два места, как заявлено в ТЗ:

- карточка выбора режима («работа создаётся искусственным интеллектом…»);
- caption готового файла: «⚠️ ЭТА РАБОТА СОЗДАНА ИСКУССТВЕННЫМ ИНТЕЛЛЕКТОМ.
  ИИ МОЖЕТ ОШИБАТЬСЯ — проверьте факты…».

| `_ensure_min_bibliography` | Если реальных источников мало, список «добивался» выдумками до `MIN_REAL_SOURCES` |
| вся цепочка | Существование DOI и URL не проверялось никогда |

### Что стало

Новый модуль **`sources_real.py`** (732 строки) — единственный поставщик источников:

- Искать в Crossref, OpenAlex и Semantic Scholar (все три API без ключей).
- **Каждая** запись проверяется живым HTTP-запросом: DOI — через handle-API
  doi.org, сайты — через HEAD/GET. Не подтвердилось — в список не попадает.
- Заголовки-пустышки (15 шаблонов вроде «404», «Результаты поиска», «Материал с сайта»)
  отбрасываются.
- Форматирование по ГОСТ Р 7.0.5, алфавитная сортировка (сначала кириллица).
- **Список никогда не добивается.** Лучше 8 настоящих источников, чем 20 с подделками:
  список литературы проверяют первым делом, и один несуществующий DOI снимает всю работу.

Ссылки пользователя теперь тоже обрабатываются честно: страница скачивается, из неё
берутся заголовок, автор, дата и название сайта.

## 2. Ссылки в тексте: больше нет выдуманных страниц

Самый опасный из найденных дефектов. Если модель не указала страницу, бот её
вычислял арифметикой:

```python
return str(12 + (int(n) * 17) % 150)   # удалено
```

То есть ссылка `[3, с. 63]` не имела отношения к источнику №3. Проверяется это за
минуту и является прямым основанием снять работу.

Убраны три способа выдумать страницу:

1. `_pseudo_page_for_source` — арифметическая формула выше.
2. `_fallback_citation_page` — таблица `{"1": "12", "2": "45"}` и «безопасная» страница 12.
3. `_nearest_page_from_map` — брал страницу чужого источника (страницу №3 приписывал
   источнику №5) — такая же выдумка.

Теперь если реальной страницы нет, ссылка остаётся в виде `[5]`. Это допустимо по ГОСТ
и честно. Оборванные ссылки вроде `[5, с. ]` тоже сворачиваются в `[5]`, а не
дополняются числом из воздуха.

## 3. Шаблонный текст и заглушки

Было четыре источника шаблонного текста — все отключены:

- `_stub_text` — «Данная работа посвящена исследованию темы ... В современных условиях
  данная проблематика приобретает особую актуальность». Ровно те клише, которые
  `strict_prompt` запрещает модели.
- `_generate_substantial_stub` — четыре абзаца воды с **выдуманными** ссылками
  `[1, с. 23]`, `[2, с. 56]`, `[3, с. 112]`, `[4, с. 78]`. Самый вредный вариант:
  выглядит правдоподобно и молча уезжал в готовый документ.
- `_ensure_paragraph_breaks` — дописывал три готовые фразы-пустышки ради формального
  числа абзацев. Они повторялись во всех работах и были узнаваемой подписью бота.
- `_stub_text_for_subchapter` — обёртка над предыдущей.

Логика сейчас: лучше пустой блок, который пайплайн увидит и перегенерирует другой
моделью, чем шаблон, который никто не заметит. Каждый такой случай пишется в лог
меткой `[STUB]`.

## 4. Текст должен читаться как написанный человеком

Новый модуль **`humanizer.py`** (560 строк) + второй проход генерации.

### Главный вывод, который важно понимать

Старая функция `_replace_ai_cliches` меняла одно клише на другое («в современных
условиях» → «на современном этапе»), а `_add_human_touch` вообще ничего не делала
(`return text`). Одна замена была прямо вредной: «на протяжении» → «в течение» ломает
смысл во фразах типа «на протяжении границы».

При разработке я сначала сделал агрессивную версию на регулярках. Оценка машинности
упала с 60,6 до 4,3 — и текст стал неграмматным:

> Сегодня **этая** проблематика **важен** в развитии общества [1, с. 45].

Поэтому в итоговой версии действует жёсткое правило: **неграмматный текст хуже
шаблонного**. Регулярки теперь только удаляют паразитные вводные обороты и
заменяют неизменяемые связки. Менять глаголы, существительные и согласование —
запрещено. Каждое предложение после правки проверяется и при признаках поломки
откатывается.

### Где же тогда настоящая гуманизация

Главный признак машинного текста — не слова, а **ритм**: все предложения одной
длины (разброс CV 0,20–0,35 против 0,45–0,75 у человека) и однотипные абзацы.
Регулярками это не лечится принципиально. Поэтому сделано два уровня:

1. **Правила в промпте** (`humanizer.STYLE_RULES`, теперь подмешиваются в каждый запрос
   к модели): список запрещённых фраз, требование чередовать длинные и короткие
   предложения, требование конкретики вместо «ряд авторов отмечает», разрешение
   сомневаться и спорить. Опечатки запрещены отдельным пунктом.
2. **Второй проход** (`_rewrite_if_ai_like`): если готовый раздел всё равно похож на
   генерацию, модель переписывает его. Результат принимается только при четырёх
   условиях: состав ссылок не изменился, объём в коридоре 80–125 %, оценка
   машинности реально упала, ответ не пустой. Иначе остаётся исходный вариант.

В тексте защищены от любых правок: ссылки `[N, с. X]`, формулы `$...$`, таблицы и URL.

### Честное ограничение

Грамматически безопасная чистка регулярками снижает оценку машинности всего с 62,7
до 62,6 на тестовом фрагменте. Остаток — это однообразный ритм, который может
исправить только модель. Поэтому качество живого стиля на 90 % дают пункты 1 и 2
выше, а не пост-обработка. Обещать «100 % обход детекторов» было бы обманом:
ни один генератор этого не гарантирует.

## 7. Запуск

Новые зависимости не нужны — оба модуля работают на `aiohttp`, который уже есть в
`requirements.txt`. Ключи API для поиска источников не требуются: Crossref, OpenAlex и
хэндл-API doi.org открыты.

```bash
pip install -r requirements.txt
python3 main.py
```

Переменные окружения остались теми же (`BOT_TOKEN`, `OPENROUTER_KEY`, `DEEPSEEK_KEY`,
`GROQ_KEY` и прочие из `.env`). Полезные ручки для источников:

- `MIN_REAL_SOURCES` — теперь это ориентир, а не обязательство: если проверенных
  источников меньше, бот напишет в лог и отдаст сколько есть.
- `FILL_UNKNOWN_CITATION_PAGES` — больше не может выдумать страницу; неизвестная
  страница означает ссылку вида `[N]`.

В логах появились метки: `[LIT]` — источники, `[HUMAN]` — стиль и рерайт,
`[STUB]` — блок, который модель не сгенерировала, `[FMT]` — абзацы.

## 8. Что осталось слабым местом

Чтобы не создавать ложного ощущения, что всё идеально:

1. `main.py` — 13 900 строк в одном файле. Работает, но развивать тяжело.
2. Около 110 блоков `except Exception` глотают ошибки молча — сбои трудно заметить.
3. Поиск источников опирается на англоязычные каталоги. Для узко российских тем
   (КоНсультантПлюс, еLibrary, КиберЛенинка) полезен ключ Serper или Google CSE —
   модуль готов к такому расширению.
4. Автоматического прогона полного сценария «тема → готовый DOCX» нет: он требует
   живых ключей API и сети. Первый запуск лучше сделать на короткой работе на 5
   страниц и глазами проверить список литературы.

# ИТЕРАЦИЯ 7 (v3.5) — правки по обратной связи: честность, ссылки, дубли, кодировка

## 1. Меню и режимы — честность вместо рекламы
- Кнопка «🆓 Бесплатно (быстро)» → «🆓 Бесплатно»: слово «быстро» удалено,
  генерация занимает минуты — обещать скорость было неправдой.
- Кнопка «⭐ Платный режим (безлимит)» удалена из меню. Любое нажатие старой
  кнопки из старых сообщений безопасно переводится в бесплатный режим.
- Убраны скрытые апгрейды «бесплатный → платный» при выборе изображений и в
  потоке своих фото; изображения теперь явно бесплатная опция (открытые источники).
- Убраны рекламные строки «Хотите без ожидания? Платный режим…» из сообщения
  об ожидании и предупреждения о нагрузке, строка «Платные: безлимитно» из
  статуса лимитов и «Платный режим» из справки /help.
- В описании режима честно указано время генерации: примерно 5–20 минут.
- Сообщение о лимите страниц больше не отправляет пользователя в платный режим.

## 2. Библиография и ссылки [N]
- «Слабые» кандидаты (score 1–3) теперь тоже проходят строгую проверку по теме:
  нерелевантный источник хуже короткого списка.
- `_match_citations_to_sources` больше не приписывает абзацу случайный источник
  по общим словам («анализ», «развитие», «проблема»): требуется минимум 2
  содержательных слова (список `_GENERIC_ACADEMIC_WORDS`), реально встречающихся
  в названии источника; в абзацы, где ссылка уже есть, вторая не добавляется.
- `_fix_citations`: номер ссылки вне диапазона списка литературы больше НЕ
  «заворачивается по кругу» на случайный источник ((num-1) % N — удалено),
  такая ссылка аккуратно удаляется из текста с логом `[CITE]`.

## 3. Повторяющиеся названия параграфов — запрещены на трёх уровнях
- Структура: `_dedupe_chapter_titles` теперь ловит и почти-дубли
  («1.1 Понятие права» / «1.1 Понятие прав», difflib >= 0.78), а не только
  точные совпадения; фоллбэк-структура тоже проходит дедупликацию.
- DOCX: новый `_dedupe_doc_blocks` перед построением содержания удаляет
  дубликаты глав и параграфов по всей работе, текст дубля приклеивается к
  предыдущему разделу — ничего не теряется.
- Содержание (TOC): дедуп перенесён ДО add_toc — раньше содержание могло
  показывать повторяющиеся названия, которых уже нет в теле документа.
